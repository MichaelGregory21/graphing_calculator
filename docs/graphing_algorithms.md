# Graphing Algorithms

## Purpose

The graphing system converts mathematically defined expressions into drawable geometric primitives.

It must support:

- ordinary functions;
- implicit equations;
- inequalities;
- piecewise expressions;
- conditional expressions;
- expressions restricted by sets;
- discrete sets;
- undefined numerical regions.

Graphing operates independently of rendering. The graphing system determines **what geometry exists**; the renderer determines **how it is displayed**.

## Ordinary Functions

For an ordinary function

$$
y=f(x),
$$

the graph is generated by sampling the function over the visible coordinate region.

The initial algorithm should use **adaptive sampling** rather than a uniform fixed-resolution grid.

A segment between two sampled points may be subdivided when:

- the function changes rapidly;
- the segment spans a large screen-space distance;
- curvature is sufficiently high;
- endpoint behavior suggests a discontinuity;
- one endpoint is defined while the other is undefined.

Subdivision continues until the segment is sufficiently well behaved or a computational budget is reached.

Undefined samples terminate the current drawable segment.

This prevents lines from being incorrectly drawn across discontinuities such as:

$$
f(x)=\frac{1}{x}.
$$

## Conditional and Set-Restricted Functions

A function may contain an explicit condition:

$$
f(x)=x^2 \text{ if } x<0
$$

or a set-membership condition:

$$
f(x)=x^2 \text{ if } x\in A.
$$

At each candidate sample, the graphing system evaluates the applicable condition before emitting geometry.

If the condition is false, no graph point is produced for that input.

For example:

$$
x^2 \text{ if } x\in\{x\in N:x<100\}
$$

is evaluated only for values of `x` belonging to the specified set.

This supports both continuous and discrete restrictions.

For a continuous set such as:

$$
\{x\in R:x<0\},
$$

the graph can be sampled over the permitted interval.

For a discrete set such as `N`, the graphing system should generate geometry appropriate to discrete points rather than connecting unrelated samples into a continuous curve.

## Implicit Equations

For equations such as:

$$
x^2+y^2=25,
$$

the initial algorithm should use **Marching Squares** over the visible coordinate region.

The expression is evaluated at the corners of each grid cell. Cells whose values indicate that the zero contour crosses the cell are identified, and the contour is interpolated along the corresponding cell edges.

Grid resolution should adapt to the current viewport and available computational budget.

## Inequalities

For inequalities such as:

$$
x^2+y^2<25,
$$

the graphing system determines the sign of the expression over a grid.

Cells that are entirely inside or outside the region can be classified directly. Boundary cells are refined to obtain a more accurate boundary.

The resulting region is converted into drawable geometry suitable for filling and boundary rendering.

## Piecewise and Conditional Expressions

Piecewise and conditional expressions are evaluated normally at each sample.

Graphing does not require special sampling algorithms for individual branches.

A change between applicable branches may cause a discontinuity or sharp transition. Adaptive sampling must therefore be capable of terminating or subdividing segments at such boundaries.

A false `if` condition produces no value and therefore creates a graph gap.

## Set Restrictions

Set restrictions are evaluated through ordinary mathematical membership.

For:

x^2 if x in A

the graphing system determines whether each candidate `x` belongs to `A`.

The graphing system must not depend on a separate domain metadata structure.

A set restriction can therefore be composed from arbitrary supported set expressions:

x^2 if x in (A ∪ B)

or:

x^2 if x in ({x in N : x < 100} ∪ {x > 100})

where the resulting set can be evaluated by the mathematical engine.

## Continuous and Discrete Sets

The graphing system should distinguish between sets that describe continuous regions and sets whose elements are discrete.

For example:

{x in R : 0 < x < 1}

contains a continuum of real values and can be sampled as an interval.

In contrast:

{x in N : x < 5}

contains only:

{0, 1, 2, 3, 4}

and should not be rendered as though every real value between zero and four were included.

The semantic/set model should provide sufficient information for graphing to choose the appropriate representation.

## Set Construction Limits

The graphing system should not attempt to resolve arbitrarily complex sets.

Set membership should be evaluated through the mathematical engine using finite computational budgets.

If membership cannot be determined within the available budget, the graphing operation should terminate gracefully rather than blocking indefinitely.

## Numerical Undefinedness

Numerical undefinedness remains independent of set restrictions.

A candidate point may:
1. fail the conditional restriction;
2. satisfy the restriction but evaluate to an undefined numerical result;
3. satisfy the restriction and evaluate successfully.

Only the third case produces an ordinary graph point.

For example:

$$
\sqrt{x}\text{ if }x\in R
$$

still produces no graph points for negative `x`.

## Computational Budgets

Graphing algorithms must have explicit computational limits.

Expensive adaptive subdivision, implicit-grid refinement, or set-membership evaluation must terminate when its budget is exhausted rather than blocking indefinitely.

The implementation should expose sufficient control internally to balance:

- geometric accuracy;
- viewport size;
- expression complexity;
- set complexity;
- computation time.
